# 偏好排序中的长度偏差：订单问答 CPU 对照实验

给定两条订单记录、一个指定订单和两个候选回答，训练打分器选出状态正确的回答。模型是从零学习两个系数的线性排序器。训练数据来自程序生成的标签，结论限于这组中文模板。

## 复现与代码走读

在本目录运行 `python -B run.py`。仅需 Python 3.8+，实测环境为 Windows、Python 3.8.2、CPU。源码已包含 micrograd，无需下载模型。每次运行会重新生成本目录的三份 JSONL 和 results.json。

1. `make_pairs` 为每个问题生成目标订单和干扰订单，两者状态不同。负例有两种：编造证据外状态，或把干扰订单的状态给目标订单。程序保留正确答案作为 chosen，排序器只从 prompt 和一条候选回答计算分数。
2. 同一批 400 个训练问题生成两个版本。正确回答较长的比例分别为 95% 和 50%。题目、正确状态、错误状态、模型、步数和训练顺序均保持一致。测试使用新订单编号和固定种子，160 对里正确答案较长和较短各 80 对。训练和测试共享句式与状态词。
3. `features` 提取回答字符数除以 20，以及回答中的状态词是否出现在证据中。分数等于两项特征与权重的内积。两个回答共用同一组权重。
4. `train` 计算分差 d = r(chosen) − r(rejected)，最小化 log(1 + exp(−d))。错排且分差越大，损失越高。实现采用数值稳定的 softplus，脚本用有限差分核对自定义梯度。固定 SGD 学习率 0.03，训练 6 轮。
5. `evaluate` 对每对回答比较分数，正确计 1、平局计 0.5。输出总体、两种长度方向和两种错误类型的 pairwise accuracy。JSONL 可逐行核对，权重和分组指标见 results.json。

## 实测与错误分析

| 测试切片 | 总对数 | 总选长答案 | 95% 长正确训练 | 50% 长正确训练 |
|---|---:|---:|---:|---:|
| 全部 | 160 | 80/160 | 143/160 | 143/160 |
| 错答更长 | 80 | 0/80 | 63/80 | 63/80 |
| 对答更长 | 80 | 80/80 | 80/80 | 80/80 |
| 证据外状态 | 120 | 57/120 | 120/120 | 120/120 |
| 错绑另一订单 | 40 | 23/40 | 23/40 | 23/40 |

平衡前后，长度权重从 1.952 降至 0.046。同一回答多 20 个字符、状态词命中情况固定时，这两个值就是各自的加分。两次训练的长度系数都为正，因此两条回答的证据特征相同时，模型仍然选较长者。错绑组中较长答案恰好有 23 次正确。

打开 test.jsonl 找 test-16：所问订单为“待发货”，另一笔为“已签收”。正确短答和错误长答都命中一个证据状态词。现有特征抹掉了订单与状态的对应关系。用精确解析器处理这个结构化任务本来就可行，适合当规则上限。该任务的实验价值在于暴露 reward 的捷径。
